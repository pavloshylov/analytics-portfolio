Payment Funnel Audit — In-App Store

Synthetic data · issues were planted to demonstrate the audit method
Three drops in the funnel, three different kinds of problem — and only one of them is urgent.
  1. Android 5.2 bug — the payment-method list fails to load for about a third of checkouts. ≈ $30.6k revenue lost per month (11% of revenue). Fix first.
  2. 3-D Secure on mobile web — users complete only 64% of card challenges vs 89% elsewhere. ≈ $2.1k per month. UX fix.
  3. iOS "Buy" clicks without checkout — the biggest-looking gap is not a loss: users close the price confirmation dialog by choice. Treating it as a broken button would book ≈ $20.7k/month of losses that don't exist.

Three cells stand out against the other platforms (highlighted): iOS Buy → Checkout, Android Checkout → Payment method, and mobile web Submit → Success. Each is examined below — they turn out to be three different kinds of problem.

Android 5.2 Release Bug

Checkout → payment method selected, daily

Since the 5.2 release (2026-08-31) only 51% of Android 5.2 checkouts reach payment-method selection, vs 80% on 5.1 over the same days and the same level on other platforms. 65% of 5.2 drop-offs log a payment_methods_error event (vs 0% on 5.1) — the payment-method list fails to load. At the current adoption this costs ≈ $30.6k per month. Next step: hotfix or roll back 5.2, and add an alert on step conversion by app version so the next regression is caught in a day, not weeks.

Buy Clicks Without Checkout User behaviour

What happened after a "Buy" click, by platform

On iOS only 73% of "Buy" clicks reach checkout vs 97% on other platforms — it looks like a broken button. But 25% of iOS clicks end with price_dialog_closed: the app shows a price confirmation and users decide not to continue. The unexplained remainder on iOS (2.5%) is no worse than elsewhere (3.3%–3.5%). Not a bug — no engineering fix needed. If the dialog itself is worth questioning, that is a product decision to A/B test, not a defect.

3-D Secure on Mobile Web UX / payments

Card payments: share of 3-D Secure challenges the user completed

Mobile-web users complete 64% of 3-D Secure challenges vs 89% on other platforms. Card payments without a challenge succeed at the same rate as elsewhere (91%), so the problem is the challenge step itself, not card declines. ≈ $2.1k per month. Next step: check how the challenge renders in mobile browsers (embedded frame vs redirect, switching to the bank app and back), and whether low-value payments can use a 3-D Secure exemption.

Priorities

Revenue impact = lost conversions × downstream conversion × average order value, scaled to 30 days. Android uses the run-rate of the last 7 days (85% of Android users on 5.2).

How the funnel was measured (SQL)

One row per session with a flag per step, then aggregated by platform. The same session table feeds every query in the audit.
